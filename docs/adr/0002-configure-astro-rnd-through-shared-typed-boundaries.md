# Configure Astro RND Through Shared Typed Boundaries

Astro getup exposes `RndCfg` as the public typed playground configuration boundary and relies on the existing recursive dataclass serialization to produce the RSL-RL dictionary; an RND-specific adapter would duplicate the generic conversion and create another contract to keep in sync. `astro_getup_ppo_runner_cfg` remains the single runner factory, with keyword-only `l2c2` and `rnd` flags defaulting to `False`; registrations explicitly choose extension combinations rather than introducing a duplicate RND factory or runner. The baseline registration explicitly selects L2C2 on and RND off, while the opt-in RND experiment selects L2C2 on and RND on, keeping RND as the isolated algorithm-extension difference. The Astro RND branch states every concrete `RndCfg` value in the experiment factory even when it matches reusable defaults, accepting local duplication so experiment parameters stay auditable and resist drift if shared defaults change.
